# Agent-profile PR: the three body-gates that red in sequence

An implementer PR that changes `agents/<profile>/` must pass THREE body-reading gates before CI goes green. They read the LIVE PR body (`check_pr_hygiene.py`, issues #1589/#1706), so fixing the body then `gh run rerun <run> --failed` is the recovery — a body edit alone does NOT re-trigger CI (`#1706`). Sequence observed on #1689 (PR #1750) and #1644 (PR #1743):

1. **check-pr-closing** (`check_pr_closing.py check`): the claimed issue needs an adjacent plain close in BOTH the commit/squash text and the PR body. A subject ending `(#N)` or an `Issue: #N` line is a CLAIM, not a close — mismatch reds ("squash commit text does not adjacently close a claimed issue" / "commit and PR body close different issues"). Fix = amend the commit to carry a plain `closes #N` line, force-push with lease + `--force-if-includes`, and rerun. (Both #1689 and #1644 hit exactly this.)
2. **check-pr-agents-line** (issue #792): the body must carry the LITERAL `AGENTS: <sha> <bytes>b <lines>l` line (plus BASE) exactly as `make bot-preflight` prints it — e.g. `AGENTS: 98c76aae... 91766b 1363l`. A hand-written variant fails; run `make bot-preflight` and paste its output. PR_BASE default is `origin/main`; a branch base not equal to the base ref reds on `check-pr-base` instead (issue #845).
3. **check-pr-sync-line** (issue #1724): only when the diff touches `agents/<profile>/` — add `SYNC: <profile> make sync-agent-profile PROFILE=<profile>` (regex `^SYNC:\s+([A-Za-z0-9_-]+)\s+make sync-agent-profile PROFILE=\1\s*$`). The literal body line is the implementer's job; ACTUALLY RUNNING the live re-sync is the profile-owning lane's duty — flag it to that lane and post it on the issue.

4. **`check-pr-base` is the 4th, and it reds on a MOVING main, not on your diff** (issue #845): `cd ci-unit` runs `check_pr_base.py check --base origin/main --rev HEAD` and demands `merge-base(origin/main, HEAD) == origin/main` — i.e. the branch tip must have been rebased onto the tip the RUNNER fetches, not the tip you fetched before your last push. Measured on PR #2077: guard + ci-scope fully green at `661fc459` (rebased onto `ea8c239e`), then `linux / unit` red at `04:10:20` with `[check-pr-base] FAILED … measured against origin/main at 54ee0d6c` — main had landed two PRs while the 13-minute unit row ran. Read the failing STEP NAME first: a `linux / unit` red is not automatically a test failure. Remedy = `git fetch origin '+refs/heads/main:refs/remotes/origin/main'`, rebase, `make check-pr-base` locally, force-push ONCE with lease, and re-stamp `AGENTS:`/`BASE:` from a fresh `make bot-preflight` (the sha they cite must be reachable from head and base). Expect this treadmill on a busy night; it is not a defect in your change.

Agent-productive checks (ci-verdict, linux/unit, lint, openspec, agents-read) stay PENDING/skipped until the scope+guard jobs settle; `linux/unit` is the long pole (~12 min) and ci-verdict flips to success only after every other row is green. A "fully green" claim is only the wire read with zero in_progress/queued AND zero red — never a queued/attempt-1 snapshot (`#1721` read-the-actual-log rule).
