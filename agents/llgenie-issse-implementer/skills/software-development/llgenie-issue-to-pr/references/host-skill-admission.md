# Admitting a procedure as a HOST_SKILL

A HOST_SKILL is a skill that lives in the tree (`.hermes/skills/<name>/`) and is
admitted by the gate `scripts/check_agent_skills.py`. `HOST_SKILLS` is a Python set in
that script. Admission touches five surfaces; miss one and a gate goes red.

## The five surfaces (all required)

1. **The skill file** `.hermes/skills/<name>/SKILL.md`
   - YAML frontmatter with `name: <name>` and a short `description:` (the index caps it
     ~60 chars; the gate's report prints `description=yes`).
   - The body MUST carry the EXACT headings `## Inputs`, `## Output`, `## Rules`.
     `REQUIRED_SECTIONS` matches these exact strings — `## When to Use`, `## Hard rules`
     and `## Pitfalls` do NOT satisfy them.

2. **The gate set** — add the name to `HOST_SKILLS` in `scripts/check_agent_skills.py`.
   Every other test must use a subset/`in`/`sorted()[0]` check on HOST_SKILLS, never an
   exact-list equality (that reds on the next legitimate addition).

3. **README** — `.hermes/skills/README.md`: name it in the existing HOST-skill
   paragraph. Do NOT add a second paragraph; exactly one such paragraph.

4. **Admission tests** in `tests/test_agent_skills.py` — mirror the existing host-skill
   pair, adapted to the new name:
   - positive: this tree admits `<name>` as a host-skill (gate findings empty).
   - negative #1: removing `<name>` from `HOST_SKILLS` turns the gate RED with a
     `skill-unused` finding for `<name>`.
   - negative #2: removing the `## Rules` section turns the gate RED with a
     rules-missing finding.

5. **Docs trio** (see `references/change-note-fragment-trio.md`):
   `agent-wiki/<date>-<slug>.md` note + `docs/changes.d/<date>-<slug>.md` fragment + the
   `CHANGES.md` row generated by `make changes-index`.

## Pitfalls

- **Verbatim body vs gate contract.** An issue that supplies the skill text "verbatim"
  in a `## Technical` section supplies the PROCEDURE (When to Use / numbered steps /
  Hard rules / Pitfalls) — it does NOT carry the `## Inputs`/`## Output`/`## Rules`
  headings the gate requires. Commit the verbatim procedure AND add the three contract
  sections. Do not drop the verbatim facts (keep-both, force-with-lease leading-tuple,
  zero-checks, capacity-vs-defect) — they are acceptance criteria; do not skip the gate
  headings either.

- **Brittle assertion on a heading word.** A negative-control test that asserts
  `"## Rules" not in body` trips on the literal `## Rules` appearing inside verbatim
  Pitfalls prose. Assert the real gate outcome (the findings list contains a
  rules-missing entry), never absence-of-substring across the whole file.

- **Trailing newline.** Every new tracked file must end with `\n` or check-docs /
  lint_linefeeds reds. Append the newline and `git commit --amend --no-edit` BEFORE
  pushing; re-run the gate after the amend.

- **Author + closes gate.** Commit as `Asimov Agent` (author gate); the commit must
  carry `closes #<n>` (`check-pr-closing`) and the PR body carries `closes #<n>` plus the
  `AGENTS:` line (`test_pr_hygiene_agents_line`).

- **Extracting a fenced skill body from an issue strips at the first nested fence.**
  Re-extract by section boundary (from the `markdown` fence to the next prose heading),
  not by naive fence-pairing.

## Definition of done (verification)

An acceptance like "`make check-agent-skills` is green" means run the MAKE TARGET, not
just the raw script. Run every named make target at the committed head:
`make check-agent-skills`, `make agent-skills-report` (must print
`<name>: host-skill ... description=yes`), `make check-docs`, `make check-wiring`,
`make changes-index-report`. Then let the FULL `make test-unit` suite conclude before
claiming the task complete — a green component test is not a green suite; claiming done
mid-suite is premature (a periodic integrity check will flag it).
