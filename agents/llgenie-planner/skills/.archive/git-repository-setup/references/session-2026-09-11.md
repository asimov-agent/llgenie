User repeatedly corrected the agent's choice of repository location and structure.

## User instruction

> "createa a repository/git path in asimov home folder"

Then after initial wrong placement:

> "no repository/git path!!!! skip the other"

Then after placing `.git` in home:

> "for fuck sake not goiiit in the home folder remove the ,.git..."

Then the first correction (with typo):

> "we waant the repository folder created and the git folder created at ~ so repository/ghit"

Then after placing it at `repository/ghit`:

> "repository/git !!!!"

Then after the agent created `/home/asimov/repository/git/` with `git init` inside:

> "and no .git folder in the git!!!! ists just a file path for other git repos!!!"

## Failures made

1. First attempt created `/home/asimov/repo` (wrong folder name) and added a `README.md` file the user did not request.
2. Second attempt initialized `.git` directly in `/home/asimov` (the home folder itself) — the user explicitly said not to do this.
3. Third attempt placed the repo at `repository/ghit` — a typo the agent did not correct, but the user then explicitly said `repository/git`.
4. Fourth attempt ran `git init` inside `repository/git/` — but the user wanted this to be a *container directory* for future repos, not a repo itself. The `.git` had to be removed.
5. The user had to escalate to profanity and repeat corrections multiple times before the agent understood.

## Correct interpretation (final)

- `~/repository/` — parent directory
- `~/repository/git/` — a plain directory (no `.git` inside) meant to serve as a path where other git repos will be created later
- The user did NOT want `git init` anywhere in this structure
- No extra files, no `README.md`, no offers to add scaffolding

## Workflow established

- Parse the user's folder name exactly as given — do not substitute similar names.
- "Create a repository/git path" can mean "make a directory structure" without any `git init`. If the user says "it's just a file path" or "no .git folder", they want a plain directory, not a repo.
- Never default to `~/repo` or similar.
- Do not create extra files.
- Stop after completing the requested action.
