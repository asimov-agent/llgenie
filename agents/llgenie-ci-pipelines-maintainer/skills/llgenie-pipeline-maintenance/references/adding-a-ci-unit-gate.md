# Adding a new ci-unit gate (issue #1924 pattern)

A new `make check-<gate>` wired into `ci-unit` has hard obligations beyond the recipe:

1. `##` help line + `.PHONY` entry in the Makefile (a phony target with a documented `##` line).
2. **`scripts/issue_bot_gates.py` DEFERRED entry with a reason** — a ci-unit gate unclassified FAST or DEFERRED reds `tests/test_issue_bot_gates.py::test_the_real_tree_is_wired`. FAST_GATES is the fixed #475 six — never widen; add to DEFERRED.
3. **docs**: the `##` help line makes it user-facing, so `make check-docs` reds unless it's documented in README or docs/ — host/CI gates go in `docs/BOTS.md` near `profile-drift`/`check-agent-profiles`. `make check-wiring` verifies the target exists and is reached.
4. **openspec**: an openspec change needs delta-style specs (`## ADDED Requirements` + `### Requirement:` + `#### Scenario:` with `- **Given/When/Then**` + `- **Test:**`), NOT prose headings. The `openspec` CLI is absent on the host — use `make openspec-validate NAME=<change>` (it runs the container).
5. **change-note**: `docs/changes.d/<date>-<stem>.md` is EXACTLY ONE pipe-table row ending `\n` (a section header + row is "holds N lines"), then `make changes-index` renders the CHANGES.md row; plus `agent-wiki/<stem>.md` note naming the issue.
6. **The gate's own mutation test must prove it catches a broken anchor** (#745): plant a stale test id / broken symbol -> gate reds; restore -> green. A read-only gate needs a byte-identical-after test (assert live+tree unchanged after a run).
7. **AGENTS/BASE lines go in the PR BODY** (not only the commit): after `gh pr create`, `gh api pulls/N -X PATCH -F body=@file`, then verify the wire body carries `AGENTS: <sha> <bytes>b <lines>l` and `BASE: <sha> (== origin/main at open)` — the guard evaluates the LIVE body, so a body fix needs `gh api repos/$REPO/actions/runs/N/rerun -X POST`.
8. **Live<->tree diff bounds**: the shared Hermes bundled library (`~/.hermes/skills`, `.archive/`, `.hub/`, `.bundled_manifest`, hidden dirs) is NOT lane behaviour and must be excluded (mirror `check_agent_profiles._bookkeeping`, `installed_library_names`, and the sibling `<hermes-home>/skills`). Report only the tree-mirrored skill surface.
9. Repo `origin` remote may be the STALE fork — always confirm the canonical `upstream` (`asimov-agent/llgenie`); base the branch off `upstream/main` fetched at that moment.
10. If main advanced after dispatch, the PR's merge-base != base reds `check-pr-base` — that's the REBASE lane's job (@llgenie-pr-merge-conflict), not this lane's; pass the PR number + current head + dispatched base.
11. **A PR that edits `agents/<profile>/` needs `SYNC: <p> make sync-agent-profile PROFILE=<p>` lines in the BODY** (#1724). But the FULL `make sync-agent-profile` is REFUSED when the live profile holds newer/truncating content in *unrelated* files (the live is the moving reference; `agent_profile_sync.py` refuses on `newer_than_source` + `shrinks`). **Never `--force` the full sync** — that is the truncation #1924 exists to prevent. And **never resolve this with a bare `cp tree <file> -> live <file>`**: the live copy of the SAME file is routinely ahead of the tree, so a targeted copy destroys live-only lessons while looking like the targeted fix. Measured: a scoped `cp` of a slimmed `SKILL.md` over live silently dropped 39 live-only lines and 2 in a second profile; the byte-size check did not notice because the file still ended up smaller for the right reason too. The order that survives is: **(a)** back up the live target first; **(b)** read the live file, compute the set of live lines absent from the tree file AND all its `references/`, and **version those lines into the tree** (this is the direction the refusal is asking for — the tree is the fixed side); **(c)** only then propagate, and **verify zero loss against the pre-copy backup, not against the tree**: every pre-copy live line must still exist in the live body plus its references. A sync claim that has not been checked against a pre-copy snapshot is unchecked, and `CHECK=1` reporting the file as identical proves byte-equality, not that anything was preserved.
12. **A flat disk floor is a false-green for an oversized cell.** The #1893 `Disk headroom` step passed a cell at 107 GiB free (flat 30 GiB floor) that then ENOSPC'd 17 minutes later on a 145 GiB host (run 42326740375, issue #1915). When a gate's constant can't express the real per-case requirement, make it per-row: carry the requirement in `matrix()` (a committed `OVERSIZED_DISK_GB` map + a `disk_floor_gb` field), read it in the workflow env (`${{ matrix.disk_floor_gb }}`), and mutation-prove it BOTH ways (flat-constant reds; dropping the map entry reds). Keep the default unchanged (30) so ordinary cells aren't newly reddened, and keep the out-of-scope cell (rocm/#1696) absent from the map — this is my lane's own class (#1893/#1895 shape, #1915 per-cell).
13. **A decision input that CANNOT express the fact is not conservatism, it is a silent skip.** A merge/label field masks what it is used to infer: `mergeStateStatus` reports `BLOCKED` whenever a review is pending *or a check is failing*, so it can never say `BEHIND` for a branch that is behind AND red — a classifier keying on that field alone returns "nothing to do" and passes over exactly the item it exists to handle, while printing a green run. Whenever a gate or sweep keys on a platform LABEL (a merge state, a status, a size), ask what masks it and measure the fact DIRECTLY. Hold the definition in ONE place shared with the gate that enforces it (a small pure function on the gate's own module, imported by the consumer) so the two cannot drift, and return a third value for "could not measure" — a failed read must never decode as "not behind". Prove it by keeping the label path intact and asserting it is UNCHANGED without the measurement (`outcome("BLOCKED") is NONE` still), so the test shows the measurement added the answer rather than a faked state. Then narrow the sibling rule that defers work on a red item — the deferral keyed on the state STRING (`if red and state == "BEHIND"`) and therefore never fired on a red item — to key on the measured fact instead, and keep its negative test (red + measured-fresh ⇒ still the other owner's).
14. **A gate wired only into a job that another job's red can SKIP is not a gate — and a skipped job reads exactly like a passing one.** `linux` declares `needs: [ci-images, guard]`, so any `guard` red skips the entire matrix. A new check wired only into `ci-unit` therefore executes ZERO times on exactly the runs that have a red, and nothing in the job list says so: the gate is green by absence. Measured: `ci-scope` had explicitly selected the row (`job=linux/unit run — class …`) and it still never ran. **Wire a cheap new gate into the ALWAYS-RUNNING job as well** (`guard` here — seconds of work when the gate only reads files and compares), and **prove it executed** by reading the step's own conclusion at a red head (`gh api repos/$R/actions/jobs/<id> --jq '.steps[]|select(.name|test("<gate>"))'`), never from the run's colour. A gate nobody can show ran is documentation.
15. **Proving a NEW gate reds needs a real run id, and producing one may require a throwaway PR.** A local `make` invocation does not satisfy a dispatch that asks for a run id. Recipe: push a short-lived branch that plants the bug, open a PR whose title says it is a sabotage proof, read the failing step from the job log, then close the PR, delete the branch, and confirm the planted file is byte-unmodified at the real head. Record the RED and GREEN run/job ids as a pair — the real PR's own CI often cannot reach a new gate at all (item 14), which is precisely why the proof must be built separately.
