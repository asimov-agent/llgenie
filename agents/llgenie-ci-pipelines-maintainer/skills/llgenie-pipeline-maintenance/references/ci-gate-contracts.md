# Gate contracts for a pipeline-file change (llgenie)

Every change this lane ships (new make target, new workflow, changed gate) must satisfy
merged gates that are easy to miss because they read *shape*, not behaviour. Satisfy them in
the same atomic commit, then prove each one green at the pushed head.

## 1. New user-facing make target → check-docs

`ci-scope`'s `check-docs` gate (whole-token match) reds on any user-facing target that is not
documented in a docs surface. Fix it by documenting the target where structurally similar
targets already live (engine gates → `docs/ENGINES.md`, next to the sibling targets), not by
adding a docs-exceptions entry. Place it adjacent to the related rows so the matcher's context
is right.

## 2. Behaviour/workflow change → change note

A change to behaviour owes a change note: an `agent-wiki/` entry **plus** a `changes.d`
fragment, with `CHANGES.md` regenerated by `make changes-index` — never hand-edit `CHANGES.md`.

## 3. change->note reads the COMMITTED tree

The `change->note` rule diffs the committed tree against a base ref; an uncommitted docs fix is
invisible to it. If the fix is still unstaged when you verify, the rule reds. Amend the single
atomic commit (own branch only) so HEAD carries the note, then re-verify.

Prove the guard catches the bug before you trust it: run the rule against the tree *before*
the note is committed (it names the violation), then after (zero). A rule only ever run on the
fixed tree has demonstrated nothing.

## 4. The worktree container cannot resolve the git base

In the container harness the mounted worktree's `.git` pointer does not resolve, so the
`change->note` rule self-skips (empty base). That self-skip is a harness artifact, not your
files — prove the rule on the host instead, passing the real base sha:

```python
import check_docs as cd
from pathlib import Path
print(cd.change_note_problems(Path('.'), '<base-sha>'))   # expect []
```

## 5. Publishing and head propagation

- Open the PR with `gh pr create --body-file` — the `--input` JSON form breaks on a title with
escaped characters and silently returns help text instead of creating the PR. After creating,
read the PR back (`headRefOid`, `mergeable`, body `closes #N` count) before reporting.
- After a force-push of an amended commit the PR `headRefOid` lags by seconds. Poll
  `headRefOid` until it equals the amended sha, then read CI runs at that sha — reading too early
  reports the old, already-red head.
- Confirm the previously-red gate genuinely turned green at the NEW sha (e.g. `ci-scope`
  `conclusion: success`), and check the sibling jobs on the same run, before claiming the fix
  landed.

## 6. Verifying a docs-gate fix at HEAD (cheap, local)

```bash
grep -c '<new-target-name>' docs/ENGINES.md        # >=1: documented
git ls-remote origin <branch> | cut -f1            # == git rev-parse HEAD
git rev-parse HEAD
```

## 7. Waiting on heavyweight CI jobs

`linux / unit` and multi-job `CI` runs take many minutes. A foreground poll loop hits the
terminal cap (420s timeouts, 600s foreground max). Launch the wait once as a background
process with `notify_on_complete` and stand on its notification instead of re-polling in the
foreground; a single `gh api .../runs/<id>/jobs` read is enough to report interim state.
