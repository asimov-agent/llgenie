# The empty-queue own-domain audit — deliverable shape and mechanics

When this lane's reactive queue is empty, the lane is not done: it runs a bounded own-domain audit and
produces its own next finding. Two domains: **engine-cell pin validity** (a pin that is silently
unsatisfiable before a build blows up) and **serving drift** (a published/declared capability that no
longer matches what users pull). Pin mechanics live in `pin-audit.md`; the trust/registry checks in
`registry-contract-following.md`.

## The audit OWES a committed in-tree record — "measurement only" is not "no change"

The completion guard measures the TREE, not the wire. An audit that produces only a filed issue plus
comments is reported as "no task-relative changed path" and the task reads as abandoned, however green
the measurements were. Every idle-audit lane's precedent ships a docs-only PR with three artefacts in
one commit:

- `agent-wiki/<date>-<topic>-audit-<issue>.md` — prose: the measured sha, what was enumerated, the
  finding(s), each finding's destination issue, and the explicit "routed to the normal queue, not this
  lane's own pass" statement.
- `docs/changes.d/<date>-<topic>-audit-<issue>.md` — exactly ONE markdown table row:
  `| <date> | <summary> | [<stem>.md](agent-wiki/<stem>.md) | #<issue> |`.
- `CHANGES.md` — regenerated by `make changes-index`, never hand-edited.

Copy the shape from an existing precedent (`ls agent-wiki/ | grep audit`, read its note AND its
`docs/changes.d` row) instead of inventing a format. Run `make changes-index`, `make check-docs`,
`make lint` before committing. The record PR is docs-only, so it needs no `SYNC:` line; it does need
the `AGENTS:`/`BASE:` header lines.

## A finding is never implemented by the lane that found it

File the finding as a refined six-section issue (Problem / Why it matters / How we fix it / Benefit /
Acceptance criteria / Technical), label it `agent:refined` (+ `continuous-improvement`), and cross-
reference the earlier issue it recurs from. The record PR cites the finding but **does not close it** —
add the justify-open note (`does not close #<finding> because this is a measurement-and-record change`)
or `check-pr-closing` reds; see `pr-gate-and-rebase-recovery.md`.

## Build the publish matrix with the repo's own resolver, not hand-rolled curl

For the per-engine×variant liveness sweep, drive the repo's OWN naming + manifest code — the same
pair the publish gate (`tests/.../test_check_engine_pins_published.py`) uses — instead of writing
scope/manifest curl queries by hand:

```python
from scripts.engine_image import resolve            # -> full ghcr ref for a committed params file
from scripts.<probe module> import _digest_http     # -> published digest or 404/None
```

Hand-rolled `curl` on `ghcr.io/asimov-agent/llgenie/llama.cpp*` or `…/exllamav3-rocm` returns **HTTP
403**, and a malformed tags-scope query returns `tags=0` for every image — both of which read as
"nothing published" and invent false gaps. 403 is a probe-encoding fault (dots/dashes in the image
name), never evidence; only a clean **404 (MANIFEST_UNKNOWN)** from the resolved exact tag is a real
publish gap. Also classify a `resolve()` **error** separately: an engine that raises
"metal-only / no frozen params / not servable" (e.g. an mlx/metal-only variant) has no container
image expected and is not a gap.

## Proving a publish-gap finding, in order

A "missing immutable tag" claim is only real once each of these held:

1. Recompute the tag the current committed params would produce — the tag scheme is
   `llgenie/<engine>:<pin8>-<hash8>-<variant>`, where the hash covers the variant's params, its
   Dockerfile, `containers/engines/entrypoint.sh` and `scripts/engine_runner.py`. Stale params mean a
   stale hash, so compute it from the audited sha, not from an installed launcher on the host.
2. Probe the full registry path `ghcr.io/asimov-agent/llgenie/<engine>:<tag>` — a bare `llgenie/<engine>:`
   path 404s because it is double-prefixed by the registry client. Probe with both docker and an HTTP
   HEAD/GET of the manifest; agreeing 404s is evidence, one 404 from one client is not.
3. Show the moving `:cuda` / `:latest` refs still EXIST at an older digest — that is what separates
   "publish-gap" from "never built, engine disabled".
4. Confirm the cell is actually enabled: present in `make matrix --ci`, absent from `DISABLED`, with a
   binary manifest entry. A disabled cell publishing nothing is expected, not a finding.
5. Check whether a live engine-build run is already about to publish it before filing, and cite the
   last relevant main engine-build run id + conclusion — a FAILED build at that ref is the mechanism.

The classification to carry into the finding: pin-missing (ref unresolvable upstream) vs publish-gap
(ref valid, image absent) vs expected-disable. Only the publish-gap class is repairable by a narrow
re-dispatch of that one `engine × arch` cell with `push=true`, then a `scripts/ghcr_publish_probe.sh`
read-back of `PUBLISHED` before the cell counts as resolved.

## A clean audit still gets recorded

`re-audited at <sha>, no findings` is a result, and it goes in the same committed record — the corpus
of audit notes is how a future lane knows a domain was actually swept rather than assumed fine.
A re-audit reproduces the earlier record PR's shape but does **not close the audit-home issue**: the
home collects re-audits and stays OPEN. Cite it in the record and say so in "Not covered".
Report the record PR, the audited sha, the finding issue (if any) and the explicit list of what was
checked to the planner.
