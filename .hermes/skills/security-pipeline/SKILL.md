# The security pipeline

This is the contract an agent runs when it is asked to work a **security leg** on this repository.
It is a HOST skill: no CI leg preloads it, and it is admitted by name in `HOST_SKILLS`
(`scripts/check_agent_skills.py`), so admitting it was a reviewed diff. Before it reads a workflow or
a script, an agent starts from this contract — the four legs, the shape of the two files that decide
each run, and the one rule every leg shares ("green or nothing").

## Tools

The security pipeline is driven entirely by `make` targets and the small scripts they call. There is
no second code path: the daily workflow, a developer and CI call the same targets.

## Inputs

- **`data/security-policy.json`** — scan failure + issue policy (issue #715, event scoping #738).
  It is the single source of truth for:
  - `fail_on`: what a daily `full` run fails on (`critical`, `high`).
  - `pr_fail_on`: the narrower set a report-only run would use — empty means **report-only**
    (findings counted, printed, uploaded as SARIF, filed as issues; run exits 0).
  - `enforce_events`: the ONLY events that may fail the run (`schedule`, `workflow_dispatch`);
    `push` / `pull_request` are forbidden (the scan is its own daily pipeline and can never gate a
    push or a PR — `make check-security-scan` refuses them).
  - `require_fix: true`: an advisory with no fixed version is **recorded, never blocking**.
  - `issue_severities`: what `make security-issues` (#716) turns into a tagged issue.
- **`.github/workflows/security-scan.yml`** — the daily pipeline (Trivy + Syft + Grype + Semgrep)
  from pinned images; a guard job runs **before any scanner** and allows only the owner, the
  repository bot on a same-repo head, or a collaborator with `admin`/`maintain`/`write`.
- **`docs/SCANS.md`** — the readable explanation of triggers, the floor loop, and green-or-nothing.

## Output

- A change this lane completes lands as **one PR** on the leg's own branch (`fix/security-floors` for
  the bot, the issue's branch for a remediation), with a body carrying `Issue: / Fix: / Benefit: /
  Technical:` and a `closes #<n>` per matched tagged issue.
- A finding the pipeline files is **one issue per (advisory, package)** — idempotent, tagged
  (`security` + `vulnerability` [+ `auto-fixable`]); never one issue per scan run.
- A gate that is red produces **no PR and no edit**: the leg reverts, comments the real output on the
  issue, and exits non-zero.

## Rules

- **`enforce_events` is data, never a literal in a workflow step.** The only events that may fail the
  run are the names in `data/security-policy.json`. An explicit `ENFORCE=pr` dispatch or any other
  event is report-only (count, print, SARIF, file issues, exit 0).
- **`pr_fail_on` is empty, on purpose.** A report-only run uses the narrower set; leave it empty
  unless the policy owner changes the decision.
- **The floor is the maximum of the minimums.** Per package, `scripts/security_bumps.py` takes the
  lowest fixed version that clears every advisory the report lists for it. Only a finding with a
  fixed version becomes a floor; the value is always the scanner's own `fixed`, never invented.
- **A compiled `requirements*.txt` is never an edit target.** `tools/requirements.in` and
  `tools/requirements-dev.in` are edited; the compiled files are regenerated by
  `make -C tools generate-requirements` / `generate-requirements-dev` — the ONE generator (AGENTS.md).
- **Green or nothing.** When a gate the leg runs is red, revert the edit, comment the real output on
  the issue, and open no PR. Never merge, never push to `main`, never force-push.
- **Never add an `automerge` key to `renovate.json`.** Every Renovate rule sets `automergeType: pr`
  and `platformAutomerge: false`; `make check-renovate` fails when the config automerges more than
  low-risk updates or lets Renovate own the Actions (#718).
- **The routing invariant is the security page's headline (issue #780/#349):** a gate nobody watches
  is not a gate. The run-failure reactor routes a failed run to a fix or a deduped issue by matching
  the workflow's top-level `name:` verbatim; the one deliberate exemption is `security-scan`, whose
  red is owned by `make security-issues` + `security-bot` (its reason lives in
  `tests/fixtures/workflow-run-exemptions.json`). Do not add an exemption without a dated reason.
- **A merged PR's bare `closes #N` never clears a scan-evidence box (issue #1693).** Only the
  pipeline's own `make security-issues-reconcile` may clear one, by naming a genuine completed scan
  (run id + sha) that no longer reports the finding; a still-reported finding is re-opened.
- **Refuse what the lane cannot place.** A `component:container` advisory (a base-image or scanner
  bump — a reviewed change) or a package pinned nowhere the leg can see is refused on the issue, never
  guessed.
