# A red head is not merged

Issue: #1386.

`mergeStateStatus` said pull request #1401 was blocked on a review. The head's `scope` check had already failed (`make ci-lint`, run 41325509945, job 124904531947). The recheck treated the review as the only blocker, approved, and ran `gh pr merge --admin`. That bypasses branch protection. The same fallback merged #1399 and #1397. #1385 and #1374 are the same class: `ci-verdict` and `linux / unit` had failed on the head, and the pull request still merged.

The merge gate now reads the head's check-runs. A conclusion of `failure`, `timed_out`, or `startup_failure` defers the pull request. It does not approve it, and it does not use `--admin`. The deferral names the check, the run, the job, and the first failing step. `skipped` and `cancelled` are not a red pipeline. A docs-only pull request has no `linux` job, and a cancelled run is not a failed test (issue #843).

`make check-merge-on-red` is that read. It exits non-zero when the head is red. `make alert-merged-red` comments once on a recently merged pull request whose head is still red, and it names the merge commit. A green re-run of the merge commit is not evidence the head was green. The recheck job runs that alert. The approver stays `github.token`.
