## What was verified

- `recheck` gained `--record <issue>`: after the pass it posts exactly ONE comment on the named
  issue — first line `[sweep <UTC-stamp>] merged=N approved=N deferred=N`, then one line per
  deferral THIS sweep decided (`- PR #<n>: <reason>`). Without `--record`, behavior is unchanged.
- The tally counts the sweep's own acts via a single `outcome` dict threaded through
  `run/_merge/_clear_review/_merge_review_cleared/defer` (`_record()` helper); callers outside
  recheck pass `outcome=None` and are byte-identical to before.
- `make auto-merge-recheck [RECORD=<issue>]` forwards `--record`; the `auto-merge` lane's recheck
  step now runs `make auto-merge-recheck REPO="$REPO" MAX=50 RECORD=2652`.
- Tests (tests/test_auto_merge.py): the deferral record with reason line, the merged count, the
  approved+refused-merge shape, `--dry` posts nothing, no `--record` posts nothing, and the lane
  wiring pin. `python3 -m pytest tests/test_auto_merge.py -q` → rc=0, 119 passed at head of this
  branch.
- Live proof: one real recorded sweep from this branch posts its `[sweep …]` comment on #2652
  (comment id quoted in the PR body).

## Key decisions

- #2652 is a permanent rolling tracker: the PR carries `Issue: #2652` with NO closing keyword.
- Dry mode prints the record body instead of posting it.
- Approvals count the review the sweep posted; a merge GitHub still refused counts as a deferral
  with its refusal reason.
