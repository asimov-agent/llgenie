# VRAM-range scope filter (issue #227) — 2026-11-07

**Implements:** issue #227 — keep the full vendored `data/models.json` verbatim and
add an explicit, TESTED filter layer scoping llgenie's view to the VRAM band it
targets (read-time filtered view, never a sync-time drop).

## What changed

- **`scripts/model_engine_pick.py`**
  - `scope_models(registry, vram_range=DEFAULT_VRAM_RANGE)` — the single, pure
    filter. Returns a NEW registry holding the models whose README `vram_tier`
    falls in `[lo, hi]`; never mutates the input; never drops data from the file.
  - `DEFAULT_VRAM_RANGE = (8.0, 48.0)` — the consumer/workstation band, documented
    with its provenance beside the constant.
  - `scope_vram_gb(model)` / `model_in_scope(model, vram_range)` — the read image
    the filter uses; `None` (a CPU/Apple-only row with a non-numeric tier) is
    always in scope (issue #227: "Apple/CPU rows are in scope (they are today)").
  - `effective_vram_range(vram_range)` — resolves `None` to `LLGENIE_VRAM_RANGE`
    (`"lo,hi"` GB) else the default; the "ask for a bigger/smaller box" seam.
  - Consumers now read the scoped view: `trend_list`, `rank_models`, `recommend`,
    `offer`, `matrix` each take `vram_range` (default the consumer band) and
    funnel the request through `trend_list`, which applies `scope_models`.
- **`tests/fixtures/vram-scope-view.json`** — the committed default-band view
  (sorted in-scope ids, counts, the range and its provenance note),
  regenerated by `make render-vram-scope-view`, CI-checked by
  `make check-vram-scope-view` (a change to the filter or the range is a
  reviewable diff). Wired into the `ci-unit` roster and `.PHONY`.
- **`tests/test_vram_scope_filter.py`** — drives the filter at multiple ranges:
  the default band (out-of-band filtered), a wide range that includes the
  128 GB `cyber-frost-3.8-mlx` (which reappears — filtered, not dropped), a
  narrow-low range that includes the 2 GB entries, plus consumer routing, the
  env override, purity and the real-vendored-store invariants.
- **OpenSpec change** `openspec/changes/vram-range-scope-view/`.

## Verified

- `make check-vram-scope-view` and `make check-trend-list-matrix` green
  (`trend-list-matrix.json` regenerated: its diff is the out-of-band rows the
  default band now drops from the matrix view).
- New filter tests green in `llgenie/test`.
