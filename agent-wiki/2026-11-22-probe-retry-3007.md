# Bounded retry before a dead-probe verdict (issue #3007)

Date: 2026-11-22. Issue: #3007. OpenSpec change: `probe-retry-3007`.

## What was verified
- The `ci-hf-live` battery (run `45010151478`) failed on `Qwen3.8-27B-UD-IQ2_S.gguf` and a local `check-quant-catalog LIVE=1` replay minutes later failed on `Qwen3.8-27B-UD-Q6_K_L.gguf`, while `curl -I` on the same URLs answered `HTTP 302` three times in a row — a single Hub probe blip was being classified `dead` because `_probe_status` had no retry budget.
- `scripts/gen_trending_quant_catalog.py::_probe_status` now spends `PROBE_ATTEMPTS = 3` probes (with `PROBE_RETRY_BACKOFF` sleeps between them) before committing to `PROBE_DEAD`: a 404/410, 5xx, timeout, or transport error is retried; 200/206 still short-circuits to `PROBE_OK`; `gated` (401/403) still answers on the FIRST probe and is never retried (#418 — a credential-gated URL is not a dead one). Classification happens only on the final answer.
- The retry lives inside `_probe_status`, the shared live classifier, so compare/carry_over/generator paths are all flake-hardened at once; the hermetic replay paths (compare/carry_over) never hit it unless a live probe is explicitly injected.
- `tests/test_quant_catalog_compare.py` measures the retry policy over real loopback sockets: `Handler.SCRIPTS` scripts per-request status codes (code `0` hangs up → transport-error class) and `Handler.HITS` counts them. New tests: 404,404,200 → `ok` after 3 probes (compare note "still reachable (ok)"); transport hang-up then 200 → `ok` after 2; 404 forever → `dead` after exactly `PROBE_ATTEMPTS`, loud in the output; 401 → `gated` with exactly 1 probe; 200 → 1 probe. `tests/test_quant_generator_edges.py` pins the same counts through the patched-urllib classifier. Targeted battery: 42 passed.
- `make -s check-wiring`, `make -s check-package-layers`, `make -s check-quant-catalog` all rc=0.

## Key decisions
- Only dead-candidate statuses spend the retry budget; `gated` is stable by definition and costs one request.
- Dead verdict wording stays "404/410" so gate output semantics are unchanged; the retry only decides WHETHER the verdict fires.
- The backoff tuple is injectable (`backoff=(0.0, 0.0)` in tests) so retry proofs cost no wall-clock.

## Current status
Mechanism + tests on `feat/probe-retry-3007`; the lane's landing record is the next `ci-hf-live` green on `main` (no single-probe flake).
