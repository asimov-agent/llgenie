# engines: ship Surogate as a cuda engine skill — #1962

The weekly registry sync surfaced the engine **Surogate** (invergent-ai/surogate) as
unskilled: it is not a case for exclusion. It is a genuine active Apache-2.0 CUDA serving
engine that publishes a manylinux cu130 wheel and an OpenAI-compatible API
(`/v1/chat/completions`, `/v1/models`, `/health`) and serves GGUF and safetensors checkpoints
(`surogate serve <hf-id|dir|.gguf> --host --port --served-model-name`).

**Resolution: ship it.** The vendored 2026-10-31 registry predates Surogate (it appeared in
the upstream store 2026-11-04). The full store sync is correctly blocked on 7 unrelated
upstream post removals the additive-only gate refuses, so this change carries **only** the
additive Surogate entry (engine row + its `qwen3.8-flash-next-125b` measurement row) into
`data/models.json`/`measurements.json` — nothing removed, `check-registry-keys` stays green.

Shipped artifacts:

- `skills/engines/surogate/SKILL.md` — pinned `v1.5.15` (`ad6c0bbf…`), Apache-2.0, installs
  the published `surogate-<ver>+cu130-cp312-abi3-manylinux_2_39_x86_64.whl` (the wheel IS the
  engine; cu130 ABI is upstream's stated floor) into the shared cuda base, launch
  `surogate serve {model} --host --port --served-model-name`, health `GET /health`.
- `containers/engines/params/surogate.json` + `containers/engines/dockerfiles/surogate/Dockerfile.cuda`
  generated by `make generate-engine-params ENGINE=surogate`.
- `scripts/engine_source_guard.py` `KNOWN_NOT_SOURCE` for `(surogate, cuda)`: the wheel is
  the precompiled product, so there is no source build step (litert precedent).
- `.github/workflows/engine-build-pr-trigger.yml` + `Makefile`: the trigger now passes
  `BRANCH="<head_ref>"` (and `make engine-build-pr-trigger` forwards `--branch`) so a
  pull_request cell dispatches at its source branch rather than the detached `HEAD` ref
  (HTTP 422 "No ref found for: HEAD", same fix #1696 carries).

`binary_probe: {cuda: device}` — `surogate --help` imports `_surogate` (the CUDA engine), which
needs `libcuda.so.1` present only at runtime, so the build-time/CI flag probe is skipped and the
version is proven by the image's own `detect` (`importlib.metadata`) — vllm precedent.
