# 2026-10-14 — the PR fix-bot: repair a red PR, re-check, never merge (#222)

## Why

A red PR waits for a human to read a log, decide whether the code or the test is wrong, fix it
and push — while AGENTS.md's gates (no skipped tests, business logic never mocked, Makefile-driven
verification) mean the fixer has to know the house rules. The sibling repo
`andyholst/trending-local-llms` runs a fix-bot that closes that loop; llgenie's CI differs
(matrices, engine images, a wiring guard), so this models it: same shape (dispatch → bounded
loop → re-check → publish only on green), different checks.

## What landed

- **`scripts/fix_loop.sh`** — check → agent → re-check, `FIX_ROUNDS` (default **3**), exit 0 green
  / 1 still red / 2 misconfigured. It never commits, pushes, merges or touches git at all: the
  workflow publishes, and only on green.
- **`scripts/fix_bot_rules.md`** — the agent's contract: fix the code by default; a test may be
  updated only when the test is provably wrong; never mock the system under test, never
  weaken/skip/delete an assertion; verify through the Makefile; do not edit workflows to change an
  outcome; no credentials in files.
- **`.github/workflows/fix-bot.yml`** — `workflow_dispatch` **only** (no `workflow_run`: a
  bot-authored PR must not re-trigger the bot, a lesson the sibling repo documents), concurrency
  per PR/branch, an owner/write-access guard, PR resolution that refuses `main`, PAT checkout +
  **one commit** push (so CI re-runs on the new head), a PR comment either way, never a merge.
- **`ci.yml`'s `dispatch-fixbot`** — `failure() && pull_request && same-repo && !draft`, capped by
  counting the bot's own `fix(bot):` commits (3), and it *comments the cap* instead of looping.
- **`scripts/install_hermes_ci.sh`** — the install seam (already installed → `HERMES_INSTALL_URL` →
  `uv tool install`), and a loud failure otherwise: a fix-bot with no agent must not report a
  permanent "still red".

## Tests (real loop, stub agent on PATH — the same allowance the repo already uses for `gh`)

`tests/test_fix_loop.py`, 15 cases: green on the first check spends no round; it stops as soon as
the repair sticks (exactly 2 rounds for a fix that lands on the second call); the default is three
attempts then exit 1; `FIX_ROUNDS` is honoured; a bad round count, a missing rules file or a
missing agent exit 2 and attempt nothing; a crashed agent does not skip the re-check; the rules
*and* the failure reach the agent; the summary comment fences the tail, names the command and says
it does not merge; and the loop leaves `HEAD`, the index and the remote untouched.

## Verification

`make lint` OK; `make check-wiring` OK (92 documents, 55 tests, 37 scripts, 88 run in CI, 132
targets — the new scripts and the test are wired); both workflows parse; `make openspec-validate
NAME=pr-fix-bot` valid; 15 passed.

## Boundary

- The bot never merges (AGENTS.md), and a red run pushes nothing — the failure is quoted on the PR
  for a human.
- The Hermes install is a seam: the package/URL may need pinning by the maintainer when the runner
  image changes; the failure is loud if it cannot install.
