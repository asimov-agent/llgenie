# LLGenie Implementer: bind a proof run's head_sha to the PR head it is cited for

Implements issue #1293 (ready-for-review PR, never merged). The strongest evidence a lane hands a reviewer is a
build-and-verify run that went green at a named head — but nothing bound that run's `head_sha` to the PR's
*current* head before the proof was accepted, so an engine cell that proved `abc1d3ac` read as green for a later
push it never saw. The `#1250` hold ($1250's own proof cell) read as a single generic `BLOCKED`, indistinguishable
in one glance from "the change is wrong". This adds the binding mechanism so a superseded proof cannot be
miscounted as current-head evidence.

## What changed (measured on this worktree)

- **`scripts/bind_proof.py`** — a producer-side gate: `python3 scripts/bind_proof.py --pr <n> --run <id>`
  reads the PR's current `head.sha` and each cited run's `head_sha`; exits **1** with `superseded proof at
  <old sha>… re-push or re-run` when any run's head differs from the PR head, exits **0** naming the sha when
  they match. A run head it cannot measure (gh api failure, a fixture missing a key) is exit **2** (bad
  invocation) — a gate that cannot read its input proves nothing.
- **`Makefile`** — `make bind-proof PR=<n> RUN=<id>` wraps the gate (producer-side, so recorded as host-only in
  `tests/fixtures/host-only-wiring.json`, issue #1293; CI consumes the run's head_sha instead of searching runs).
- **`.github/workflows/engine-build.yml`** — after a build-and-verify step passes, the workflow records
  `head_sha=${{ github.sha }}` to both the step summary and `$GITHUB_OUTPUT`, so the verdict a reader quotes is
  self-binding: its head is named beside the SUCCESS.
- **`scripts/check_holds.py`** — the holds audit now labels a held PR's red distinctly: a held PR whose proving
  run went green at an older head than the PR's current one reports **`superseded-proof`** (fix = re-push or
  re-run) instead of the generic no-remedy read, via a new `superseded()` helper that resolves each cited run's
  head_sha (offline fixtures may carry a literal `runs` map).
- **Tests** — `tests/test_bind_proof.py` (5) drives the real script: current-head pass, older-head fail,
  several-runs-one-stale fail, a missing run head is exit 2, `--pr` is required. `tests/test_holds.py` (+2)
  proves a superseded run is its own `superseded-proof` finding (offline) and is NOT when the run's head binds.

## Verification (measured, not asserted)

  **20 passed**.
- `make check-workflows` → OK (every YAML parses, the new engine-build step included).

## Not covered (from the issue)

- Actually re-running the engine cell on a superseded head — a lane action, not a gate.
- The `#1250` sglang content fix (already the PR under review) — this issue is the *binding* mechanism.
- The cancellation-vs-skip unreadability (`#1111`) — this issue is the superseded-proof half.

This change never weakens the gate it gates: `check_holds.py` still fails a hold with no resolving issue, and
`bind_proof.py` only ever `1`s a proof that does not bind — it makes the red's REASON readable.
