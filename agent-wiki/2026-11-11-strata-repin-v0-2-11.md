# Strata re-pinned to v0.2.11 — the newest all-variants-buildable release

- Date: 2026-11-11
- Engine: strata (skills/engines/strata/SKILL.md)
- Implements the strata engine-bump blocker for the v0.2.13 rocm link failure (issue
  title: `ci(engine): strata v0.2.12+ cannot link its rocm cell (upstream
  fused::want_dm_f16 stub gap) — re-pin bump #2266 to v0.2.11`)
- Links upstream: Niko1221/Strata#5473 (open, unmerged)

## What changed

Re-pinned Strata from v0.2.9@d94bac6a to v0.2.11@4a4160162e4a402e082f41aa0a88e6eed629d913 —
the newest release whose `src/prefill/prefill.cpp` carries zero `fused::want_dm_f16`
call sites, so BOTH the cuda and the rocm CI cells can link and build green. v0.2.12+
carries 1-2 call sites whose definitions CMake only compiles behind the OFF-by-default
`STRATA_PREFILL_MMQ` (`strata_hip_mmq()`), which is why v0.2.13@fb57f747 failed every
rocm link (engine-build runs 42950150623, 42956798213).

The move is the pin plus its generated artifacts, nothing else:

- skill front matter re-pinned (via `python3 scripts/engine_bump.py pin ...`)
- `make sync-strata-models` rewrote `data/strata_models.json` to setup.py at v0.2.11
  (adds DeepSeek-V4.1-Flash-1017-GSQ-RCO-Coder + the UD-IQ1_M quant, both present there)
- `make generate-engine-params ENGINE=strata` rewrote `params/strata.json` and both
  `Dockerfile.cuda` / `Dockerfile.rocm`

No vendor-side link stub and no `STRATA_PREFILL_MMQ=ON` enablement were added — the
no-fallback rule forbids a second code path, and toggling MMQ changes the engine's
feature mix. The v0.2.13+ bump stays deferred (tracked) until upstream #5473 merges.
