# Engine-bump runs now carry their own companions (#2865)

Issue: #2865. OpenSpec change: engine-bump-companions-2865 (specs/engine-pin-bump-companions).

## What was verified
- Root cause (measured on the 2026-11-16 bump wave, #2855-#2859 all red on one run):
  the weekly bump commits `engine_image.py` pins + regenerated params only. The
  hygiene guard refused every bump PR body for the missing `OPENSPEC:` line, the
  scope gate reported "0 work record(s) named in docs/changes.d/ and 1 missing",
  and frozen test constants (`test_engine_skills.py` vllm pin, stale
  `_image_hash` literals, `test_ci_publish_order.py`'s identical-params case)
  reddened every bump unit job.
- Fix class in `scripts/engine_bump.py`: `bump()` now writes the
  `agent-wiki/<date>-<id>-bump.md` note + `docs/changes.d/<date>-<id>-bump.md`
  row as one pair (`_write_companion_notes`, #934 pairing rule), rewrites every
  frozen `_IMAGE_HASHES`/`_image_hash` literal that the regen moved
  (`_variant_hashes` before/after + `_rewrite_frozen_hashes`), and its pin-pair
  rewriter skips historical `docs/changes.d/` rows while also moving the
  bumped engine's `skills/engines/<id>/SKILL.md` pins.
- `.github/workflows/engine-bump.yml` stages `agent-wiki/` in the bump commit
  and the PR body carries `OPENSPEC: publish-changed-pin-images` as a
  standalone line (the hygiene guard's OpenSpec requirement).
- `test_ci_publish_order.py`'s identical-params case branches on
  `ci_publish_order.retagged_engine_ids`: identical text defers only when a tag
  actually retags; it demands the publish lane when the engine moved.

## Key decisions
- History stays frozen: changes.d rows and agent-wiki notes record the pin pair
  they were born at; only live assertions/tests/docs and the engine SKILL.md
  track the new pair.
- Companion files are generated by the bump run itself, not by a follow-up
  docs lane, so every bump PR is self-sufficient for the scope gate.
