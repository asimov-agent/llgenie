# 2026-11-02-ci-empty-files-gate-1509

**`make check-empty-files`** — a zero-byte-file gate (issue #1509), wired into `ci-lint` so a PR and a main-push run it. It refuses paths the change set *adds* (`--base origin/main`, three-dot `--diff-filter=A`) that are zero bytes, and with `--all` every *present* empty tracked file — the shape that let `.wt-probe.txt` (0-byte blob `e69de29b`) ride #1467's squash to main. `.gitkeep`-style sentinels (`.gitkeep`/`.keep`/`.keepXYZ`) are the one allowed empty case; `--allow` names explicit exemptions. Script: `scripts/check_empty_files.py` (argparse, checked in via the crate-style `check`/`report` seam); unit-tested in `tests/test_check_empty_files.py` (a synthetic git repo with a 0-byte addition fails, a `.gitkeep` passes, a clean tree passes in both modes). Acceptance: a change adding an empty file FAILS naming that path; current main passes the gate (post-#1508); the gate is wired into the regular CI job; a checker is covered by a unit test. #1509.
