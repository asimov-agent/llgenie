# Strata model-map check made hermetic: committed vendor + manifest (issue #519, PR #TBD)

## What was verified against the spec (`openspec/changes/strata-check-offline/`)

- **The flake path is gone.** `make check-strata-models` (a `ci-unit` step) used to shallow-fetch
  `github.com/Niko1221/Strata` at the pinned commit on every unit run. It now compares
  `data/strata_models.json` against `extract()` re-derived from the **committed vendor tree**
  `data/vendor/strata/` (`setup.py` at the pinned sha + the `strata_control` import surface its
  module-level imports need — empirically: `__init__.py`, `acquisition.py`, `__main__.py`,
  `version.py`, `_version.py`) and never runs `git` or a socket. Proof:
  `tests/test_strata_check_hermetic.py` monkeypatches `checkout` AND `subprocess.run` to raise,
  then runs the hermetic `check` on the **committed** chain — green with zero process spawns
  (`test_the_committed_chain_is_consistent_and_hermetic`).
- **The vendor chain is manifest-verified.** `sync` writes `data/vendor/strata/manifest.json`
  with `url`/`ref`/`pinned` and a per-file sha256 map; `check` first asserts manifest pin ==
  skill pin, every recorded file hashes to its recorded sha256, and no unrecorded file sits in
  the vendor. Tampering tests cover stale pin, edited `setup.py`, smuggled extra module,
  missing vendor, hand-edited map — each refused with the repair named (`make sync-strata-models`).
- **One fetching path.** The old fetch-then-compare survives as `check-strata-models`' sibling
  `make check-strata-models-live` (explicit upstream audit, NOT a CI job; `ci-unit`'s pinned
  step list names only the hermetic one — `test_ci_unit_stage.py` passes unchanged).
  `scripts/engine_bump.py`'s `checkout()` already owned the bump's fetch; it still fetches and
  `sync-strata-models` regenerates map + vendor + manifest in one step (the only writer).
- **The bump lane carries the vendor.** `.github/workflows/engine-bump.yml`'s `git add` list
  gained `data/vendor/strata/` so a Strata pin bump commits the regenerated vendor beside the map
  and the chain can never land mid-bump-stale.
- **Gates exercised locally:** `make sync-strata-models` (vendor + manifest + map regenerated,
  map JSON byte-identical to the committed one at pin `0a80d5e5`), `make check-strata-models`
  rc=0 hermetically, targeted pytest 29 passed (hermetic + missing_hf + live_target +
  ci_unit_stage), full `make test-unit` (see below), `make openspec-validate` rc=0.

## Key decisions

- Vendor = setup.py **plus its module-level import closure**, discovered empirically during sync
  (a `ModuleNotFoundError` names the next file to vendor), not a hand-maintained list — a bump
  that moves the pin re-derives the closure from the newly pinned source.
- `load_setup` hygiene hardened for the new three-way sharing (fixture tree, live checkout,
  vendor tree in one process): stale `strata_control` entries evicted from `sys.modules` before
  each load, `sys.dont_write_bytecode` during exec, `sys.path` cleaned in `finally`. This also
  fixed the latent cross-tree import contamination the #437 note pointed at.
- Vendor lives at `data/vendor/strata/` — the natural sibling of the `data/registry/` vendoring
  the repo already practices; `.gitignore` untouched (vendor IS committed).
- The SKILL.md pin (`v0.2.15@0a80d5e5`, live-pinned by `pinned()`) was measured fresh at sync;
  `data/strata_models.json`'s `pinned` field was already `0a80d5e5` — no pin change in this lane
  (the committed map regenerated byte-identically).
- `make check-strata-models-live` is recorded as a dated host-only decision in
  `tests/fixtures/host-only-wiring.json` (target entry, decided 2026-11-19, issue 519): the wiring
  guard rejects a target whose help line references CI that no CI job delivers, unless the decision
  is registered — `make check-wiring` green with 10 host-only targets.
