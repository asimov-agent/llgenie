# 2026-11-02 check-pr-closing reads the PR body live (issue #1589)

Issue **#1589** (security-lane measured finding, routed to the pipeline lane).

## What changed

`make check-pr-closing` (guard and scope jobs in `ci.yml` / `scope.yml`) previously fed the body
from the run's **event snapshot** — `PR_BODY: ${{ github.event.pull_request.body || '' }}` — so when a
contributor fixed the body (e.g. added the adjacent `closes #N` the gate demands), a `gh run rerun`
re-executed the job against the *same* frozen payload: the gate kept seeing the stale pre-fix body and
kept failing. The only way to clear was to manufacture a new PR event (amend→new-oid→rebase→force-push),
meaningless tree churn on a doc-only PR (measured on #1581, runs `41451812717` / `41451812395`).

This change reads the body **live** in the job instead of from the event:

- Each check-pr-closing step (`ci.yml` guard, `scope.yml`) now fetches
  `gh api repos/$PR_REPO/pulls/$PR_NUMBER --jq '.body // ""'` and writes it to `/tmp/pr-body.md`,
  so a body edit clears on rerun without a new push. A push to `main` has no PR number: `PR_BODY`
  stays empty and only the squash half of the check runs (unchanged behaviour).
- The GH token is passed explicitly (`GH_TOKEN: ${{ github.token }}`) and `scope.yml` gains
  `pull-requests: read` (read-only; `ci.yml`'s guard job already inherits a token with that scope).
- The run block stays expression-free (`$PR_REPO`/`$PR_NUMBER` come from env, not `${{ }}`), so
  `test_the_guard_and_scope_steps_pass_the_base` holds.

## Do not weaken

The adjacent-keyword rule and the squash-vs-body-set rule are untouched: `scripts/check_pr_closing.py`
and the `check-pr-closing:` Makefile recipe are byte-identical; only the body's *source* changed from
event-snapshot to live API read. The gate still reds on the same claimed-issue-without-adjacent-close.
