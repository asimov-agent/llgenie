# The architecture Bot table no longer promises clocks it lost (#3091)

**Issue:** #3091 · **base:** `1d7f02406bd00307c1d122964bf08f6bbc940d29` · **owner:** `llgenie-documentation-maintainer`

## What changed

`docs/ARCHITECTURE.md` is the map a contributor or a host lane reads before touching the fleet. Its
"## Bots" table still gave a cron slot to seven workflows whose `on:` block has no `schedule:` at all:
`issue-bot.yml` (`23 6 * * *`), `issue-refiner.yml` (`43 * * * *`), `issue-dedupe.yml`
(`51 */6 * * *`), `rebase-bot.yml` (`29 */6 * * *`), `registry-sync-review.yml` (`55 * * * *`),
`search-smoke.yml` (`11 7 * * *`) and `architecture-bot.yml` (`47 */6 * * *`). #2701 de-clocked
them; #2703 classified them dispatch-only; `docs/BOTS.md:497-519` already carried the correct
dispatch-only table, so the architecture doc was the only written surface still asserting the old
rule (issue #3091, measured at `origin/main` = `0ad1e31685ec45525702a9919fd90b29fb5330c1`).

The seven `Cron` cells now read `—`, and each row's description begins
`Dispatch-only (`workflow_dispatch` only; clock off, #2701)` so the reason travels with the row.
The cell is exactly `—` and not a longer literal because the issue's proof command treats a
backtick-wrapped `—` as "workflow expects no cron"; a longer string there would be counted as a
mismatch even though the workflow is genuinely clock-free. The lead sentence no longer says every
bot owns a cron slot; it states the two trigger classes — a scheduled `schedule:` cron on a
bot-owned minute, and a manual `workflow_dispatch` with its clock off. The stage-1 sentence that
named `architecture-bot.yml`'s retired `47 */6 * * *` clock was corrected too, and the two
now-false cadence phrases on corrected rows ("four times a day" on `issue-dedupe`, "an hourly run"
on `registry-sync-review`) were removed.

The table stays bot-scoped: engine-build and gate workflows are deliberately absent (#2299), so
nothing was added. No workflow trigger, `check-ci-discipline` allow-list or `docs/BOTS.md` row
changed — those were read-only references.

## What was verified

- Issue's own proof command at the base, executed 2026-11-27T12:17Z against
  `git show origin/main:docs/ARCHITECTURE.md`: `doc rows=15 mismatches=7`, naming exactly the seven
  workflows above (negative control, so the check is reading the table, not trivially passing).
- The same command against the edited document (15 rows parsed, each workflow read from the same
  tree): `doc rows=15 mismatches=0`, empty mismatch list. The eight clocked rows — including the
  positive control `code-review-bot.yml` at `31 7 * * 1` — are unchanged.
- Extended check over all seven corrected rows: each `Cron` cell is `—`, its workflow carries
  `workflow_dispatch:`, its workflow has zero `cron:` entries, and its row carries the #2701
  rationale — `dispatch-only rows verified=7/7 problems=0`.
- `make -s check-docs` is the #1123 gate this note and its one-row `docs/changes.d/` record satisfy;
  its change→note leg reads the `origin/main...HEAD` diff. The `CHANGES.md` row is generated by
  `make changes-index` from the fragment; the index is never edited by hand (#934).

## Anything left open

- No guard was added that compares the table's cron column with the workflows' `schedule.cron`
  values. The issue lists that as optional step 4; it would change `scripts/` and the Makefile, so
  it belongs to a separate implementation lane, not this docs-only PR.
- The seven `docs/BOTS.md` dispatch-only rows and the #2701/#2703 workflow changes are already on
  `main` and were not touched here.
