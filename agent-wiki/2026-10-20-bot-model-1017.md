# The bots run DeepSeek V4.1 Flash 1017, and the pin cannot drift again

Issue #405. OpenSpec change: `bot-model-1017`. PR: #410.

## What was wrong

Every bot pin named `deepseek/deepseek-v4.1-flash`. The Nous catalogue serves that as a **different,
older** model than the snapshot the owner runs:

```
deepseek/deepseek-v4.1-flash         canonical_slug deepseek/deepseek-v4.1-flash-20260910  (Impala)
deepseek/deepseek-v4.1-flash-1017    canonical_slug deepseek/deepseek-v4.1-flash-20261017  (DeepSeek)
```

Both answer `200` (measured with a live `/v1/chat/completions` each), so no bot job could tell them
apart: issue-bot, fix-bot, issue-refiner, rebase-bot and `agent-fetch` ran the September snapshot while
`~/.hermes/config.yaml`'s `model.aliases.nous-deepseek` already ran `-1017`. The only test on the pin
was `assert "deepseek/deepseek-v4.1-flash" in script` — a family **prefix**, which any newer id
satisfies. Drift was invisible by construction.

The image's alias was also written with no `max_tokens` and no `context_window`, while the host pins
`16000` / `1048576` (the snapshot's published `context_length`). Unset, Hermes budgets the run from
models.dev, which carries no entry for this snapshot id.

## What changed

- `scripts/agent_model_pin.py` (new) — the pin declared once (`MODEL_ID`, `MAX_TOKENS`,
  `CONTEXT_WINDOW`), with `check` (names every file still behind, non-zero) and `report`. Stdlib only,
  no network, no key.
- `make check-agent-model` / `make model-pin-report`, both `.PHONY`; `ci-unit` runs the check.
- `containers/agent/Dockerfile` — `ARG HERMES_MODEL_ID` → `…-1017`, new `HERMES_MAX_TOKENS` /
  `HERMES_CONTEXT_WINDOW` build args, and the build asserts the alias's model, `max_tokens` and
  `context_window` (not just `key_env`).
- `scripts/install_hermes_ci.sh` — same pin; writes `max_tokens` + `context_window`; its post-write
  check now compares model / key_env / max_tokens / context_window and names the wrong value.
- `tests/test_agent_model_pin.py` (new) — drift in the Dockerfile, a *newer* snapshot in the install
  script, a missing pin, the budget pair, `ci-unit` reachability and `.PHONY` membership.
- `tests/test_issue_implementer.py` — asserts the exact snapshot id instead of the prefix.

## Verification

- `make check-agent-model` → `[model-pin] OK` (both files at `…-1017`).
- `pytest tests/test_agent_model_pin.py tests/test_issue_implementer.py` in `llgenie/test:latest` →
  36 passed.
- The agent image rebuilt from the changed inputs (its hash covers both files), and the image's own
  build step asserts the alias, so a wrong pin fails the BUILD.
- Live `make hermes-smoke` through `-m nous-deepseek` inside the rebuilt image — the model answers;
  see the PR body for the run's output.
- Direct endpoint probe of the pinned id: `POST /v1/chat/completions` returns
  `reasoning_content` and honours a `tools` call (`get_weather` → `tool_calls`), so both the
  reasoning flag and the tool calling every bot leg depends on work on this snapshot.

## Honest limits

- The gate is hermetic: it compares the files, it does not ask the endpoint whether the pinned id is
  still the current or still-served one. That gap is #408.
- The image hash still does not cover the Hermes version `install.sh` fetches (#406), and
  `hermes-smoke` still proves text, not tool use (#407).
- Moving the pin is a three-place edit (the module + two defaults) by design; a single-generated-file
  scheme was rejected because the Dockerfile's ARG default must be readable in the Dockerfile itself.
