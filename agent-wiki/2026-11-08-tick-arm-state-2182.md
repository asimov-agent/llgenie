# The tick arms auto-merge and reports arm state (issue #2182)

## What changed

The orchestrator tick had no step that armed auto-merge and no rule saying which
lane owns a green-but-unarmed PR, so arming depended on a lane remembering and a
parked green PR sat unmerged. Measured 2026-11-08 at `origin/main 3e2e64fa`, all
17 open PRs: **10 unarmed, 3 armed-but-DIRTY (inert), every one red `ci-verdict`**,
so none could merge. Three separate defects: nothing armed the unarmed ones, an
armed-but-DIRTY PR was indistinguishable from "armed and waiting" (DIRTY gets no
CI run and the merge queue never sees it, so the arm can never fulfil), and
arming had no read-back — `gh pr merge --auto` exits 0 and arms NOTHING when the
base is not the default branch (#964).

This change makes the tick's arming a versioned, tested part of the procedure:

- **`agents/llgenie-planner/scripts/tick_board.sh` section B** now reports arm
  state per PR: `autoMergeRequest` present/absent, `mergeStateStatus`,
  `mergeable`, `reviewDecision`, and labels each PR one of four states — `ARMED`
  (merge-queued and waiting), `unarmed`, `ARM-INERT` (armed AND DIRTY — the arm
  is impossible, never counted as handled), and `green+appr+unarm` (ready to arm
  now). It prints the `ARM   armed=N  unarmed=N  armed-but-DIRTY(inert)=N`
  summary line and the explicit `ARM-INERT is NOT handled: dispatch
  llgenie-pr-merge-conflict for the rebase` instruction.
- **The `--json` field list fix** — the false-measurement this issue exists to
  prevent. `gh pr list`/`gh pr view` return `null` silently for a field missing
  from `--json`, so an earlier section B asked for `autoMergeRequest,
  reviewDecision` and printed `armed=0` for all 17 PRs, a false measurement that
  looked authoritative. The versioned list now carries both fields, and a test
  pins that a known-armed fixture reports `ARMED` not `unarmed`.
- **`tests/test_tick_board_arm.py`** — hermetic (fixture-fed, no network) tests
  covering the four states, that `armed-but-DIRTY` is classified `ARM-INERT`
  and never counted as handled, the exit-0-but-not-armed read-back case (#964:
  `gh pr merge --auto` succeeds and changes nothing), the refusal to arm a PR
  whose head has a live run or is mid-rebase (#2069: green+armed at `cc72588c`,
  rebased, green destroyed, never merged), and the false-field-list regression
  (the section-B `--json` list must carry both arm fields).

The versioned tick prompt already carries the ordered arming step (4d measure +
4e `gh pr merge <n> --squash --auto` then read `autoMergeRequest` back as the
proof + 4f unarmed-and-not-green + 4g one-check-many-PRs routed to its tracker),
so the step is versioned under `agents/llgenie-planner/` with the rest of the
procedure (#2159) — not only in the live `jobs.json`. This change adds the
measurement and the tests that make it a tested procedure, and keeps the prompt
drift gate (`make check-tick-prompt`) green because the prompt itself was not
edited.

The planner arms, the queue merges — this step never merges by hand.
