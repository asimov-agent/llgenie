# 2026-10-17 card-aware engine ranking (issue #225)

`rank_engines` picked a model's best engine on this host by **raw t/s within a
coarse backend class** (CUDA / ROCm / Metal / CPU). A backend class has no notion
of how powerful the measuring machine was, so a figure from far beefier hardware
of the same backend became the top recommendation on a small consumer card — and
the top engine is what plain `llgenie` offers and downloads (`engines[0]`,
`--auto`, the first row of the interactive list).

## What was measured before implementing

On the vendored registry (2026-10-13), for a 16 GB CUDA card, `rank_models(...,
gb=16)` offered:

| model | engine offered first | figure | measured on |
|---|---|---|---|
| `qwen3.8-27b` | vLLM | 300 t/s | 2x RTX 4090 (48 GB) |
| `qwen3.8-flash-next-125b` | Strata | 140 t/s | RTX 3090 24GB |
| `qwen3-14b` | Ollama | 65 t/s | RTX 3090 24GB |

All three were labelled `same_hw=True` — "measured on hardware like yours" —
although the card was two to three times the user's. Run against the CURRENT
upstream registry the same code put a 21 000 t/s figure from a **single NVIDIA
B300 (datacenter)** third for a 16 GB card. Upstream's own README already states
the rule this violates: *"a measurement on a bigger card does not qualify a
smaller tier, because what it needed there is unknown"*, and *"datacenter parts
never count"* (its card-fit section, trending-local-llms #337).

## Change

`scripts/model_engine_pick.py`:

- `measurement_card_gb(hardware)` — the card a measurement ran on, from the
  registry's own free-text `hardware`: an explicit `NN GB` wins, else a known
  card model, else `None`; `2x RTX 3090` multiplies. The table and the parsing
  are upstream's (`_CARD_VRAM`, `hardware_vram_gb`), so llgenie and the README
  read a hardware string the same way.
- `datacenter_hardware(hardware)` — H100/A100/B300/MI300/GB200 … mirroring
  upstream's `_DATACENTER_HW`.
- `rank_engines(model, arch, ids, gb)` ranks `0` proven on this card class (same
  backend AND a card no bigger than this host's), `1` same backend on a bigger
  card, `2` same backend with no card named, `3` another backend, `4` datacenter,
  `5` supported without a figure; within a rank by t/s then engagement. Rows gain
  `card_gb` and `card_class`; `same_hw` keeps its meaning and is now exactly rank
  0. The card class applies only on `cuda`/`rocm`/`vulkan` hosts — Apple Silicon
  and CPU hosts are judged by unified memory / RAM, as upstream does — so a host
  whose card cannot be detected keeps yesterday's backend ranking.
- `tps_label(e)` is the ONE t/s text rule (`124 t/s`, `96 t/s (ROCm)`,
  `300 t/s (CUDA, 48 GB card)`, `67 t/s (CUDA, card unknown)`,
  `21000 t/s (CUDA, datacenter)`, `supported`); `llgenie_serve._tps_label`
  delegates to it.
- `rank_models`, `recommend` and `matrix` pass their card size into
  `rank_engines`, so the trend list's server per row (and therefore `--auto`'s
  download) is the card-aware choice.

`data/models.json` is untouched: it stays a verbatim upstream copy, and every
field this change reads (`engines[].hardware`) was already in it.

## Verification

- `tests/test_card_aware_rank.py` (new, wired into `make test-unit`): the
  hardware-string table, the datacenter list, proven-vs-bigger, the datacenter
  case, the no-card-class path, the label table, the card-aware trend list, and
  the #225 acceptance case (`qwen3.8-flash-next-125b` on a 16 GB CUDA card →
  Strata 97.3 t/s on an `RTX 5070 12GB`, proven; the 24 GB and DGX Spark rows
  labelled and below it).
- Existing tests updated for the renumbered ranks and the shared label:
  `tests/test_trend_pick.py`, `tests/test_model_engine_pick.py`,
  `tests/test_trend_list_acceptance.py`.
- `tests/fixtures/trend-list-matrix.json` regenerated by
  `make render-trend-list-matrix`: on the 16 GB rows Qwen3.8-27B's server becomes
  `llama.cpp` at 108.3 t/s (RTX 5060 Ti 16GB) instead of `vLLM` at 300 t/s
  (2x RTX 4090), and Qwen3.8-Flash-Next 125B's Strata figure becomes 97.3 instead
  of 140 — the diff is the review evidence.
- `README.md` step 2 of the interactive pick documents the rule and the labels.

Not covered here: the model-list filter itself (#227) — the list still uses the
coarse `vram_tier` in `fits()`, and upstream's card-fit evidence ladder
(`ran-on` / `weights-only` / `declared`, `vram_min`) belongs to that change.
