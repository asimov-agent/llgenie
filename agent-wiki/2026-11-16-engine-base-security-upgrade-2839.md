# Engine base security upgrade (#2839)

Date: 2026-11-16 · Issue: #2839 · OpenSpec change: `engine-base-security-upgrade`

## What was verified

- The published llama-cpp CUDA image `llama-cpp:7d7f0287-e536208a-cuda` carries 15 HIGH inherited Ubuntu debs (gnupg family ×10, `libapt-pkg6.0t64`, `libssl3t64` ×2, `openssl` ×2) — measured on published-image scan run 43787049546; these are open issues #2738-#2747, #2752, #2796, #2825, #2797, #2826.
- The engine base recipe is generated by `scripts/engine_skills.py::render_base_dockerfile`; its only apt RUN was `apt-get update && apt-get install`, so inherited distro debs were never upgraded on any rebuild.

## Key decisions

- One renderer edit: `apt-get upgrade -y` between `apt-get update` and the toolchain install (the agent-image shape proven by #2836/#2838, which cleared 68 of 91 agent findings). Generated `containers/engines/base/Dockerfile.*` files are regenerated by `make generate-engine-params`, never hand-edited.
- `base_tag` is the content hash of the rendered base, so the change moves all four base tags (e.g. cuda `6d50abe567` → `b70085bed2`) and the 24 engine Dockerfiles that build on the llgenie base re-pin their `FROM llgenie/base-<backend>:<hash>` lines with it; cells FROMing upstream images (vllm/sglang CUDA etc.) are untouched; `make check-engine-params` keeps the on-disk copies from drifting. Because the engine image tag digest hashes the committed Dockerfile bytes, the 24 re-pinned cells acquire new published tags (vllm cpu `524f7326` → `169d2720`); the pinned digest in `test_vllm_rocm_opens_its_root_only_base_venv_for_uid_1000` and the re-tag proxy in `test_ci_publish_order.py::test_a_params_file_identical_to_the_base_is_not_deferred` (now comparing tag-input files: committed Dockerfiles, entrypoint, runner) were updated for exactly this.
- Closure of the 15 finding issues belongs to the scan that clears them (post-merge main engine rebuild → next #2706 published-image scan), never to a hand close in this lane.

## Current status

- `tests/test_engine_skills.py` gains `test_engine_base_upgrades_inherited_debs` (upgrade layer between update and install in all four backends, disk file == renderer output) and `test_engine_dockerfiles_pin_the_upgraded_base_tag` (every engine FROM pins the current base tag; both FROM shapes — `AS build` and bare — accepted).
- Post-merge, the main CI engine-base + engine jobs rebuild and publish with the new base tags; the weekly scan lane reports the closures.
