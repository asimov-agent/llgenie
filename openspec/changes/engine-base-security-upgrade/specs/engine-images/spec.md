# engine-images

## ADDED Requirements

### Requirement: every compiled engine base upgrades the debs it inherits

`scripts/engine_skills.py::render_base_dockerfile` MUST run `apt-get upgrade -y` after `apt-get update` and before the build-toolchain `apt-get install`, for every backend it renders (`cpu`, `cuda`, `rocm`, `vulkan`), so distro packages inherited from the upstream base image are refreshed to what the security mirror holds current at build time. The upgrade is expressed in the renderer only; the generated `containers/engines/base/Dockerfile.<backend>` files are regenerated by `make generate-engine-params` and never hand-edited.

WHEN an engine base image is built
THEN no base-image deb is left at a version the mirror has already superseded with a fix.

#### Scenario: the base apt layer upgrades before it installs

- **Given** a generated `containers/engines/base/Dockerfile.<backend>` for each of cpu, cuda, rocm, vulkan
- **When** the base apt RUN is read
- **Then** `apt-get upgrade -y` appears between `apt-get update` and `apt-get install`
- **Test:** `tests/test_engine_skills.py::test_engine_base_upgrades_inherited_debs`

#### Scenario: the new base tag propagates into every engine build stage that consumes the base

- **Given** the regenerated engine Dockerfiles under `containers/engines/dockerfiles/`
- **When** their build stages are read
- **Then** every stage whose `FROM` names the llgenie base (bare or `AS build`) pins the tag of the rendered base it builds on, and `make check-engine-params` reports no drift; stages FROMing upstream images (vllm/sglang CUDA etc.) are untouched
- **Test:** `tests/test_engine_skills.py::test_engine_dockerfiles_pin_the_upgraded_base_tag`, plus `make check-engine-params` (`scripts/engine_skills.py params --check`) and the existing `tests/test_ci_variant_matrix.py` base-pinning assertions
