# Proposal: engine-base-security-upgrade

## Why

The published llama-cpp CUDA engine image `llama-cpp:7d7f0287-e536208a-cuda` carries 15 HIGH inherited Ubuntu packages — the gnupg family, `libapt-pkg6.0t64`, `libssl3t64` (×2) and `openssl` (×2) — measured on published-image scan run 43787049546. The shared engine base recipe is generated by `scripts/engine_skills.py::render_base_dockerfile`, and its only apt RUN is `apt-get update && apt-get install`: the debs inherited from `ubuntu:24.04` / `nvidia/cuda:13.0.2-devel-ubuntu24.04` are never upgraded, so every rebuilt engine image re-ships them and the scan re-reports them forever (issues #2738-#2747, #2752, #2796, #2825, #2797, #2826). The agent image got exactly this fix in the #2836/#2838 chain and cleared 68 of its 91 findings; the engine bases never got it. GitHub issue: #2839.

## What Changes

- `render_base_dockerfile` gains `apt-get upgrade -y` between `apt-get update` and the toolchain `apt-get install`, for every backend (`cpu`, `cuda`, `rocm`, `vulkan`). The one renderer is the only edit; the generated `containers/engines/base/Dockerfile.*` files are regenerated, never hand-edited.
- The base image tag is the content hash of the rendered Dockerfile (`base_tag`), so the change moves all four base tags, and every engine Dockerfile's `FROM llgenie/base-<backend>:<hash> AS build` line is regenerated by `make generate-engine-params`; `make check-engine-params` guards the on-disk copies against drift.
- `tests/test_engine_skills.py` gains a hermetic test pinning `apt-get upgrade -y` between update and install in all four generated base files; the existing matrix/bump tests already read `base_tag()` dynamically and prove the engine-side pinning moves with it.
- After the merge the pipeline does the rest (not an acceptance criterion here): the main CI engine-base + engine jobs rebuild and publish with the new base tag, and the next published-image scan (#2706 lane) closes the 15 findings itself — no hand closures.

## Impact

- Affected specs: `engine-images` (this change adds the base-upgrade requirement).
- Affected code: `scripts/engine_skills.py`, regenerated `containers/engines/base/Dockerfile.*` and `containers/engines/dockerfiles/*/Dockerfile.*` (generated), `tests/test_engine_skills.py`.
- Affected GitHub state: issue #2839 body synced; the 15 finding issues close only via the scan that clears them.
