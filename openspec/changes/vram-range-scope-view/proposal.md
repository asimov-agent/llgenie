# vram-range-scope-view — proposal

Issue: [#227](https://github.com/asimov-agent/llgenie/issues/227)

## Why

The full vendored `data/models.json` (every model, every VRAM tier — including
the 128 GB `cyber-frost-3.8-mlx` and the 2 GB entries) is the source of truth
and must stay verbatim: `make sync-registry` vendors the whole registry and
drops no row. But llgenie's operating scope is a *view*: it targets the
8–48 GB consumer/workstation band today, and the same code must work on a 128
GB box — or a 2 GB one — when asked. Today that scope is implicit: each
consumer filters `fits()` ad hoc, with no single place that says "this is the
set llgenie works with for range R", so it is untested and easy to get subtly
wrong.

## What Changes

- **`scope_models(registry, vram_range=DEFAULT_VRAM_RANGE)`** in
  `scripts/model_engine_pick.py`: a single, pure, TESTED filter that turns the
  full registry into the set llgenie works with for a range, defaulting to the
  consumer band (8–48 GB VRAM). It is a pure function of `(registry, range)`,
  never mutates the registry, and never drops data from the file — a wider or
  narrower range just changes the returned view.
- **Route the consumers through it**: `trend_list`, `recommend`, `offer`,
  `matrix`, and `rank_models` each accept `vram_range` and read the scoped
  view, so the pick and the per-`(arch, ram, vram)` matrix all share one
  filter rule instead of ad-hoc per-call checks.
- **A committed default-range view** (`tests/fixtures/vram-scope-view.json`),
  regenerated by `make render-vram-scope-view` and CI-checked by
  `make check-vram-scope-view` — a change to the filter (or a register
  widening of the range) shows up as a reviewable diff.
- **The range and its provenance documented once**: `DEFAULT_VRAM_RANGE` and
  the consumer-band rationale live beside the filter and in this change's
  record, so why 8–48 GB is answerable.
- Tests drive the filter at more than one range (the default band AND a wide
  range that includes the 128 GB entry), proving out-of-band entries are
  filtered out of the default view, never dropped from the file, and reappear
  when the range includes them.

## Not covered

- Ranking-rule changes (#225) — out of scope for this change.
- Analysis → issues widening (#231) — out of scope for this change.
- Changing `make sync-registry` / dropping rows from `data/models.json` — this
  change keeps the vendored file verbatim.

Refs: #223/#226 (the sync-gate fix and the sync PR this came from), #227 (this
change), #228 (the mock `(arch, ram, vram)` grid this filter feeds).
