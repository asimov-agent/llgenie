# fix-engine-base-upgrade — proposal

Issue: [#2839](https://github.com/asimov-agent/llgenie/issues/2839)

## Why

The published llama-cpp CUDA engine image
`ghcr.io/asimov-agent/llgenie/llama-cpp:7d7f0287-e536208a-cuda` carries **15
HIGH-severity inherited Ubuntu packages** — the gnupg family (dirmngr, gnupg,
gnupg-utils, gnupg2, gpg, gpg-agent, gpgconf, gpgsm, gpgv, keyboxd),
`libapt-pkg6.0t64`, `libssl3t64` (×2 advisories) and `openssl` (×2 advisories)
— all at the versions baked into the upstream bases
(`nvidia/cuda:13.0.2-devel-ubuntu24.04`, `ubuntu:24.04`). The shared engine
base recipe (`containers/engines/base/Dockerfile.<backend>`, generated by
`scripts/engine_skills.py::render_base_dockerfile`) runs `apt-get update &&
apt-get install` but never upgrades the packages the base image inherited, so
every rebuilt engine image re-ships the same vulnerable debs. The
published-image scan re-reports the same advisories on every weekly run,
filing the same issues over and over, and no engine rebuild can clear them.

## What Changes

- `scripts/engine_skills.py::render_base_dockerfile` now emits
  `apt-get upgrade -y` in the base `RUN` line, right after `apt-get update`
  and before the build-toolchain `apt-get install`, on every backend (cpu,
  cuda, rocm, vulkan). This is the same standing-upgrade shape the agent image
  Dockerfile adopted in #2836/#2838.
- Regenerate every generated file with `make generate-engine-params`: the base
  tag is the content hash of the rendered Dockerfile, so all four
  `containers/engines/base/Dockerfile.<backend>` change and every engine
  Dockerfile's `FROM llgenie/base-<backend>:<hash> AS build` line moves to the
  new hash. `make check-engine-params` keeps the on-disk copies in sync.

## Impact

- Affected: `scripts/engine_skills.py`, `containers/engines/base/Dockerfile.{
  cpu,cuda,rocm,vulkan}`, and every engine Dockerfile under
  `containers/engines/dockerfiles/<id>/` whose build stage uses the shared
  base.
- After the merge, the main-CI engine-base + engine jobs rebuild and publish
  with the new base tag; the next published-image scan (#2706 lane) no longer
  reports the 15 advisories and closes those issues itself.
- Not covered (each already its own issue): the 85 open `component:container`
  findings against `agent:latest` / `test:latest` (#2836/#2838 chain, human
  publish dispatch #2837) and the upstream-pinned Go/npm clusters per the
  #2836 disposition table.
