# Change: refresh the grype scanner pin to the published Wolfi build

## Why

Issue #3096: `make scanner-freshness` at `origin/main` reported `grype: pinned 0.121.3-r2 but
Wolfi published 0.122.1-r0 8 days ago (grace is 7)`. The daily `security-scan` workflow runs that
gate, so a stale detector under every Grype finding was reported green. A grace widening would
silence the signal without fixing the pin, so the published build is adopted instead.

## What Changes

- `containers/scanners/grype/Dockerfile`: `ARG GRYPE_VERSION` becomes `0.122.1-r0`; the Syft
  companion pin and the digest-pinned Wolfi base are unchanged.
- The shared `containers/scanners/digests.json` (there is no per-scanner file) is regenerated by
  `make scanner-digests`: grype `version`, content-hash `tag`/`ref` and the published manifest
  `image_digest` all describe the new Dockerfile. The new image was published through the
  scanner-image pipeline's own build+push path before the digest was pinned.
- No grace window, gate, workflow, agent instruction or product feature changes.

## Benefit

`make scanner-freshness` rc=0 against the live APKINDEX, and the scanner inventory names one
published, digest-pinned grype build that matches its Dockerfile.
