# Spec Delta — vllm-rocm-base-access (#2553)

## ADDED Requirements

### Requirement: A prebuilt base whose engine install is root-only is opened for the runtime user

An engine container spec SHALL accept a `base_access` key: a list of absolute paths inside
the base image that hold the engine install. A variant that declares `base_access` SHALL
render exactly one `RUN` between the service-user create `RUN` and the trailing
`USER 1000:1000`, which grants `o+rX` over every DIRECTORY under each declared path and over
the entries directly inside `<path>/bin`, so the uid-1000 runtime identity can traverse the
tree and execute the launcher entries.

The `RUN` SHALL NOT chmod regular files outside `<path>/bin` recursively: a recursive chmod
over the engine tree would copy it up into a new image layer.

#### Scenario: vllm/rocm Dockerfile carries the open

- **Given** the vllm skill regenerated by `make generate-engine-params` with
  `container.rocm.base_access: ["/opt/python"]`
- **When** `containers/engines/dockerfiles/vllm/Dockerfile.rocm` is read
- **Then** it contains `find "$d" -type d -exec chmod a+rx {} +` for `/opt/python` and the
  line sits after the uid-1000 create `RUN` and before `USER 1000:1000`

#### Scenario: Variants without base_access are untouched

- **Given** every other engine/arch Dockerfile in the tree
- **When** the generator runs over all skills
- **Then** no Dockerfile that does not declare `base_access` gains a base-access `RUN`
  (vllm cuda/cpu and all other engines byte-identical to before)

#### Scenario: The open is directories plus bin entries only

- **Given** the rendered base-access `RUN`
- **When** its shell body is inspected
- **Then** the recursive `find` is limited to `-type d`, and the only non-recursive chmod
  over files is `-maxdepth 1` inside `<path>/bin`

### Requirement: base_access moves only the declaring cell's tag

The generator SHALL attach `base_access` to a variant's params dict ONLY when that variant's
skill entry declares it; an undeclared variant SHALL NOT gain the key (not even an empty
list). Because the params dict is a per-variant tag-hash input, this keeps every other
cell's digest — and every already-published tag — byte-reachable.

#### Scenario: only the rocm digest moves

- **Given** `make generate-engine-params` after this change
- **When** the vllm params JSON and the tag digests are recomputed
- **Then** `variants.rocm` carries `base_access: ["/opt/python"]`, `variants.cuda` and
  `variants.cpu` carry no such key, the cuda digest stays `4c1f3eee` and the cpu digest
  stays `524f7326`, and the rocm digest moves away from `db98981b` (measured `d04739cb` after the interpreter-chain trace; `ba13b1d7` on run 43254534536 proved the chmod-only step insufficient)

#### Scenario: rocm detect and flag probes pass on a rebuilt image

- **Given** a post-merge `workflow_dispatch` engine-build for `engine=vllm arch=rocm
  push=true`
- **When** `make test-engine-stage ENGINE=vllm ARCH=rocm TEST=detect` runs in CI
- **Then** all documented flags answer (no exit 126) and detect prints the baked vllm
  version, and the run publishes the recomputed tag `vllm:3a4d82f5-ba13b1d7-rocm` to GHCR
