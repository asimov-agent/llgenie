# Proposal: Syft gets its own pinned scanner image (issue #746)

## Why

`containers/scanners/digests.json` carries an immutable image for trivy, grype and semgrep, but
Syft — the tool that WRITES the CycloneDX SBOM every Grype finding is matched against — has no
image of its own. It is reached through the Grype image with `--entrypoint syft`, so its version
is "whatever the pinned Grype build bundled". A grype bump silently changes the SBOM generator;
`make check-scanner-images` cannot see it, and `tools: syft` in the dispatch form names a ref
whose tag has nothing to do with Syft (issue #746). This is the one exception to the parent rule
(#713/#715) "one immutable image per scanner" — and it is the exception that feeds every finding.

## What Changes

- **New `containers/scanners/syft/Dockerfile`** — same contract as the other three scanners:
  Wolfi base pinned by `@sha256:` (the same digest the grype image pins), `ARG SYFT_VERSION=1.57.2-r0`
  (newest published Wolfi build, measured 2026-11-19 from `packages.wolfi.dev/os/x86_64/APKINDEX`),
  non-root `USER 65532`, `ENTRYPOINT ["syft"]`, `CMD ["version"]`. The binary comes from the Wolfi
  `syft` apk package, the same acquisition path trivy/grype/semgrep already use.
- **`scripts/scanner_image.py`**: `"syft"` joins `SCANNERS` (`arg: SYFT_VERSION`, `cmd: version`) and
  `RELEASE_BASELINE` (`1.57.2-r0`); the `BAKED_TOOLS` carve-out (`grype.syft_version`) and
  `baked_version()` are deleted — Syft is no longer a baked tool.
- **`scripts/security_scan.py`**: `sbom()` runs `image_ref("syft")` with no `--entrypoint` override;
  the published-image scan (`scan_published_image`) runs the syft image the same way;
  `_run`'s `entrypoint` parameter is dropped (no caller overrides an entrypoint anymore);
  `check()` requires a full digest entry (`version`/`tag`/`ref`/`image_digest`) for EVERY tool in
  `ALL_TOOLS` and the baked-`grype.syft_version` freshness block is replaced by that roster;
  `_pinned_scanner_versions()` reads syft's pin from `digests.json` instead of the grype
  Dockerfile's ARG; `ensure_image_for` resolves syft through `ensure_image` like the others.
- **`containers/scanners/digests.json`**: regenerated by `make scanner-digests` (four entries), then
  the syft tag is published (linux/amd64 + linux/arm64) and pinned with
  `make pin-scanner-image-digests SCANNER=syft` — the same publish/pin sequence the grype bump
  (#2716) used.
- **Docs**: `docs/SCANNERS.md` roster table + "one image per scanner" paragraph, `docs/SCANS.md`
  ("written by Syft from the Grype image" → "from its own pinned Syft image"), `CHANGES.md`
  via `docs/changes.d/`.

## Impact

- Affected specs: `scanner-images` (ADDED syft image + no-entrypoint SBOM run; MODIFIED digest
  roster; REMOVED baked-syft record requirement superseded by #2708).
- Affected code: `containers/scanners/syft/Dockerfile` (new), `scripts/scanner_image.py`,
  `scripts/security_scan.py`, `containers/scanners/digests.json`, `tests/test_scanner_images.py`,
  `tests/test_security_scan.py`, docs listed above.
- The grype image is NOT rebuilt or bumped by this change: its bundled syft simply stops being
  used. A grype Dockerfile edit changes only the grype content-hash tag, never the syft one
  (asserted in a test).
