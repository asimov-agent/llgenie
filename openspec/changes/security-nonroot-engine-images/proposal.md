# security-nonroot-engine-images — proposal

Issue: security(high) umbrella DS-0002 — 37 per-file trivy findings consolidated
into ONE objective: every shipped Dockerfile declares a non-root `USER`.
Consolidated per-file issues: #2397–#2428, #2463–#2467.

## Why

`trivy-misconfig` rule **DS-0002** ("Specify at least 1 USER command in Dockerfile
with non-root user as argument") reports against **37 shipped Dockerfiles** on `main`
(4 shared bases, 32 generated engine images, and the test image). Every engine this
repository publishes was shipped running as **root**: the scan re-reports all 37
findings on every run, and the board carried 37 one-line issues for a single family.
A container that serves an exposed HTTP API as root is a standing privilege-escalation
and host-escape risk if the engine binary is ever compromised.

## What Changes

- **`scripts/engine_skills.py`** — the ONE renderer that owns every generated
  container. `render_base_dockerfile` now ends the shared base with
  `USER 65532:65532` (the repo's established non-root user, matching
  `containers/ci-variant` and the scanners). `render_dockerfile`:
  - resets `USER root` for the build/install stage of any cell built on the shared
    base (so `engine_runner.py install` still compiles/installs as root), and
  - ends the **final runtime stage** with an owned app dir
    (`RUN chown -R 65532:65532 /opt/llgenie/app`), a writable `HOME`, and
    `USER 65532:65532` just before `HEALTHCHECK`/`ENTRYPOINT`.
- **`scripts/engine_runner.py`** — the HF cache `mkdir` is best-effort: a host-mounted
  read-only `/models` must not crash non-root serving.
- **`containers/test/Dockerfile`** — declares `USER 65532:65532` as the default image
  user; every verification stage already runs `-u root` (Makefile `TEST_OPTS`,
  `ENGINE_TEST_ARGS`), so no test changes behaviour. `CI_HOME_CLEAN` now also passes
  `-u root` (it deletes a root-owned `.ci-home`).
- **36 generated `Dockerfile.*` + 4 base `Dockerfile.<backend>`** regenerated by
  `make generate-engine-params`, so `make check-engine-params` stays green.
- **`tests/test_engine_skills.py`** — hermetic tests locking the non-root guarantee.

This is the DRY fix: the change is in the renderer, not in 37 hand-edited files, so a
future engine added to a skill gets the non-root `USER` for free and `check-engine-params`
keeps the committed files honest.

## Benefits

- Every shipped engine image (and the shared bases and the test image) serves as a
  non-root user, so a compromised engine can no longer write to the host mount or escalate.
- One PR and one trackable work item instead of 37 unlinked one-line fixes.
- The security pipeline's next `trivy-misconfig` run reports **zero** `DS-0002`
  findings on `main`.
- Adding a new engine later inherits the hardened renderer automatically.

## Out-of-scope (own issues)

- Building the ROCm/CUDA vLLM images from upstream images is tracked separately
  (#2435, #2437); this change only clears the DS-0002 findings in the files listed.
